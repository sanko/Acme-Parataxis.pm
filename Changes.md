## [Unreleased]

### Added

- New exceptions: `Acme::Parataxis::Error`, `Acme::Parataxis::Error::Cancelled`, and `Acme::Parataxis::Error::Timeout`
- `Acme::Parataxis::CancellationToken` lets any fiber register for cooperative cancellation. `cancel` interrupts every parked, registered fiber by throwing `Acme::Parataxis::Error::Cancelled` at the park site.
- `Acme::Parataxis::Local` provides a per-fiber storage slot for ambient state that must not leak across fibers (tracing ids, span context, per-fiber handles).
- `Acme::Parataxis::Generator` is a stackful, lazily-pulled iterator. Here's the synopsis demonstrating a fibonacci sequence:
```perl
my $fib = Acme::Parataxis::Generator->new( sub ($y) {
    my ( $a, $b ) = ( 0, 1 );
    while ( $a < 100 ) {
        $y->($a);
        ( $a, $b ) = ( $b, $a + $b );
    }
} );

my $total = 0;
while ( defined( my $n = $fib->next ) ) { $total += $n }   # 0 1 1 2 3 5 ...
```

- `Acme::Parataxis::Actor`: a thin actor - a dedicated fiber owning a bounded `Channel` mailbox that runs one handler per message. `Actor->spawn( sub ($self, $msg) { ... } )` returns immediately; `ask($msg)` queues the message with a reply `Future` and hands it back, so the handler's return value (or die) travels to the caller through `->await` or `->on_ready`; `send($msg)` is fire-and-forget. The bounded mailbox gives slow handlers backpressure to senders, `ask` composes with `with_timeout`/cancellation like any fiber wait, and `stop` shuts down gracefully (draining pre-stop messages, failing anything that slipped past the marker). A handler die fails its own ask (or warns for a `send`) and the actor keeps running; supervision is deliberately out of scope. A dropped handle never leaks the actor: the mailbox fiber holds the actor handle only weakly, so dropping the last strong reference asks the actor to stop and it is collected instead of lingering (regression-tested in t/044).


- `Acme::Parataxis::RateLimiter`: a token bucket for rate-limited services. `RateLimiter->new( rate => $n, burst => $m )` starts with `burst` tokens in the bucket and refills at `rate` per second; `acquire($n)` spends tokens and parks the calling fiber while the bucket cannot cover them, resuming as refills arrive. The bucket is an ordinary `Semaphore`, so a blocked acquire inherits the scheduler's whole park path: it is interruptible by `with_timeout` and cancellation tokens, unregisters itself when interrupted so no later refill can wake a fiber that no longer wants a token, and never busy-waits. Refills are driven by a `Ticker` waking `rate` times a second, each wake crediting every whole token accrued since the previous one on the wall clock (so the delivered rate holds even where timers are coarse) and only while the bucket sits below its ceiling, so an idle limiter tops itself up to `burst` and then stops. `stop` halts refills, lets any parked acquirer through rather than stranding it, and makes a later `acquire` croak instead of parking forever with nobody left to refill. Introspection: `tokens`, `waiters`, `running`, `rate`, and `burst`.







- `with_timeout( $ms, [ $token, ] $code )`: runs a block as a child fiber and throws `Acme::Parataxis::Error::Timeout` in the caller if it doesn't finish in time, cleaning up the child and anything it was blocked on while the scheduler keeps running. An optional token cancels the block early (`Error::Cancelled`); a pre-cancelled token fails fast; a bound of `0` means no deadline.
- `Acme::Parataxis::Sync`: the synchronization-primitive family, sharing one park/wake mechanism where an interrupted wait unregisters itself from the primitive it was parked on:
    - `Acme::Parataxis::Sync::Mutex`: a non-reentrant lock with true owner tracking (`lock`/`try_lock`/`unlock`/`guard`, plus `owner`/`waiters`). Releasing from a non-owner, relocking the same fiber, or releasing a free lock all croak; a contended `lock` parks and is handed directly to the next FIFO waiter, so nobody can cut in line.
    - `Acme::Parataxis::Sync::WaitGroup`: a job counter shared across fibers. `add($n)`/`done()` adjust it (over-done and non-integer adds croak) and `wait()` parks until it reaches zero.
    - `Acme::Parataxis::Sync::Barrier`: a reusable rendezvous for `parties` fibers. `arrive_and_wait` releases exactly `parties` at the phase boundary (the last arriver included) and re-arms for the next round.
    - `Acme::Parataxis::Sync::Once`: an initializer run exactly once across racing fibers. The first caller runs it (and gets the return value), concurrent callers park until it finishes, and late callers no-op; an initializer that dies still leaves the Once done.
    - `Acme::Parataxis::Sync::RwLock`: a writer-preferring read/write lock - any number of readers xor one writer. `read_lock`/`read_unlock`/`try_read_lock`/`read_guard` take shared holds (the read side is reentrant, releasing one hold per `read_unlock`); `write_lock`/`write_unlock`/`try_write_lock`/`write_guard` take the exclusive lock with `Mutex`'s owner tracking and strict FIFO hand-off. The lock is writer-preferring: once a writer is queued, new readers are held back, so a steady read stream can't starve writers, and `try_*` never park and never cut ahead of a queued waiter. A read-to-write upgrade croaks instead of deadlocking, unlocking from a non-holder croaks, and an interrupted wait unregisters - transferring any hand-off it was about to collect to the next waiter.
- Event-loop driver integration: `Acme::Parataxis->attach_loop($loop)` / `detach_loop()` / `loop()` route `await_read`/`await_write`/`await_sleep` onto an existing CPAN event loop instead of the OS worker pool, so epoll/kqueue/IOCP come for free while the scheduler, fibers and parks stay exactly as they are. The driver interface (`Acme::Parataxis::Driver`) dispatches by the attached loop's class and tracks every watch and timer it armed; `detach_loop` (and the end of any `run`) unwinds them all. Two reference drivers ship: `Acme::Parataxis::Driver::Mojo` (`Mojo::IOLoop`, one tick per idle cycle) and `Acme::Parataxis::Driver::IOAsync` (`IO::Async::Loop`). The loop's callbacks only ever enqueue fibers, never run them, so no re-entry into the scheduler is possible, and the `await_*` contract is unchanged (readiness values, `-1` on timeout, `with_timeout`/`nursery` still throw).
- `nursery( sub ($n) { ... } )`: structured concurrency. The enclosed block spawns child fibers with `$n->spawn`; the call returns only once every child is done, and the moment any child fails the rest are cancelled and drained. The first failure (together with the `Error::Cancelled` unwinds of the siblings it cancelled) is rethrown in the caller as `Acme::Parataxis::Error::Nursery`, whose `->primary` and `->failures` expose the aggregate. The block value comes back on success; a block error cancels and drains the children, then propagates unchanged; the nursery's `CancellationToken` is public as `$n->token`, so user code or a nested `with_timeout` can cancel the whole group like a failed sibling. A bare `fiber`/`spawn` inside the block is not adopted by the nursery (it is an independent fiber the block owns).
- `Acme::Parataxis::Channel::select`: CSP-style waiting on the first ready case among any number of channels. `Acme::Parataxis::Channel->select( [ $ch, 'get' ], [ $ch2, 'put', $v ], timeout => 1000, default => sub {...} )` probes ready cases without yielding, parks on the first open case otherwise, and returns `( $channel, $value )` (or `( undef, undef )` on timeout, or the default block's value when nothing is ready). Cases are tried in random order so none can starve; each case channel parks the select on its own waiter list, woken by the matching operation.
- `Acme::Parataxis::Channel::try_get` / `Acme::Parataxis::Channel::try_put`: non-blocking channel operations. They return `( $ok, $value )` / `$ok` immediately instead of parking, waking channels select-parks just like their blocking siblings.
- `Acme::Parataxis::Channel::select_waiters`: reports how many fibers are currently parked in select on a channel (introspection, for tests).
- `dump_fibers()`: diagnostics. Returns every live fiber, its state (WAITING/READY/RUNNING/RUNNABLE) and - when parked - the wait reason and the source site where it yielded (wait_reason), and prints the same as a human report when given a filehandle. The scheduler's fatal deadlock message now carries the report: each parked fiber of the deadlocked run with reason and site, instead of a bare `FATAL: deadlock detected...`, so deadlocks name their participants at a glance.
- `Acme::Parataxis::Ticker`: a drift-free interval timer. `Ticker->new( interval => $ms )` starts a background fiber that measures each period against an absolute tick boundary and sleeps only the remainder, so `while (my $t = $tick->wait_next) { do_work() }` fires on the boundary whatever `do_work` costs, instead of drifting later every cycle. Each tick is published into a capacity-1 channel after anything unread is drained, so at most one tick is ever outstanding and it is always the newest: a slow consumer silently loses periods rather than queueing a stale backlog. `stop` releases any fiber parked in `wait_next` with `undef`, interrupts the ticker fiber, and recalls the sleep job it armed, so a stopped ticker never keeps `run` alive or leaves a fiber behind. Introspection: `running`, `interval`, `pending`, `fired`, and `dropped`.
- Fiber limits: `set_max_fibers( $count )` and `max_fibers()`. The fiber table is no longer a fixed array compiled in at 1024 slots: it is allocated on demand and doubles whenever it fills, bounded by a hard internal ceiling of 1048576, so how many fibers you can create is decided by memory rather than by a compile-time constant. What bounds it as policy is the limit itself, which defaults to 65536 and is enforced against the slots in use rather than against the array, so it may be raised or lowered at any time - lowering it never disturbs fibers that already exist, it only stops the next spawn until enough of them finish, and raising it again works with no reallocation. Spawning past it croaks the same "the fiber table is full" as before, and the message now points at `set_max_fibers`. Because the table grows silently, a program that wants the old behaviour can pin it with `set_max_fibers(1024)`; t/029 does exactly that, since it is written in terms of a table that stops at 1024. t/053 covers the growth past 1024, a limit raised and used, a limit lowered and enforced against live fibers, and the raise-again case that needs no reallocation.
- `Acme::Parataxis::Supervisor`: OTP-style supervisor trees, the heal-fast counterpart to `nursery`'s fail-fast. `Supervisor->new( strategy => 'OneForOne'|'OneForAll'|'RestForOne', max_restarts => 5, within => 60 )` builds a tree; `supervise( $thing, name => $name )` registers an `Actor`, a nested `Supervisor`, or a `CODE` factory returning either (a factory that dies counts as a death of that child); `run` then supervises from inside a scheduled fiber until `stop` is called or the restart budget runs out, and either way drains every child before returning so no fiber of the tree outlives it. The strategy decides who restarts when a child dies: `OneForOne` touches only the child that died, `OneForAll` restarts the whole set (they share whatever the death broke), and `RestForOne` restarts the dead child plus everything that started after it. `max_restarts` deaths inside `within` seconds exhaust the budget, and the (max_restarts+1)-th death inside the window tears the tree down and dies with `Acme::Parataxis::Error::Supervisor`, carrying `->failures` (every death that counted, in order), `->primary` (the one that blew it), and `->child` (its name), in the style of `Error::Nursery`; `within => 0` keeps nothing in the window, so the same budget never trips. Restarts produce fresh instances: a restarted actor comes from `respawn` with a fresh mailbox (asks still in flight against the dead one are failed there, never hung or silently dropped), and a restarted supervisor is rebuilt from its configuration rather than resumed, so nested trees come back from scratch. Death reports ride a per-instance `token` through a `Channel`, so a report from an instance a `OneForAll`/`RestForOne` restart already replaced, or from an expected stop, is dropped instead of counting as a new crash. Introspection: `children`, `child`, `restarts`, `running`, `stopping`. Supervision is pure Perl on the existing park/wake machinery (one supervision fiber learns of a death through the child's own teardown), and is tested by t/054.
- `Acme::Parataxis::Actor` gained the three hooks supervision needs: `spawn( ..., supervised => 1 )` makes a handler die kill the actor instead of only failing that one ask (a `send` handler die keeps warning and keeps running unless supervised), `on_death( $cb )` registers a callback that fires exactly once when the actor is gone with the error that killed it (or `undef` for a graceful stop, immediately if it is already dead), and `respawn()` returns a fresh, already-running actor with the same handler, mailbox size, and options, which is what a supervisor starts in place of a dead child. `error()` reports why the actor died.
- Software transactional memory (STM): `Acme::Parataxis::TVar` is a versioned transactional cell, and `Acme::Parataxis->atomically( sub { ... } )` (also importable as a bare block, `&`-prototyped) runs its block as one transaction on the calling fiber - reads are journaled, writes stay in a write set, and the commit, which is all-or-nothing, first validates that every TVar the transaction read still holds its committed value, re-running the block from the top on any conflict. `retry()` aborts the transaction and parks the fiber until a TVar it read changes (croaking on an empty read set, which could never wake); nested `atomically` blocks join the enclosing transaction, so their writes commit together rather than deadlocking. Blocking on a lock is never required and lock ordering is a non-problem: two opposite transfers between the same two TVars resolve by one rolling back and re-running. `with_timeout` and cancellation interrupt a retry-parked transaction cleanly, unregistering it from every TVar it was watching. The transaction journal bears the usual STM warning: the block may run many times, so it must not have irreversible side effects (no printing, file I/O, or channel puts). t/056 covers single-writer commit exactly once, the classic deadlock resolving, write-invisibility until commit, retry-park-and-wake, nested logs, and a timeout interrupting a parked transaction.
- `Acme::Parataxis::Stream`: a chainable FRP pipeline over bounded channels. `Stream->from_channel( $ch, stage_capacity => $n )` wraps a Channel as the pipeline head; every stage - `map`, `filter`, `batch`, `batch_time`, and `throttle` - is a factory that allocates a fresh bounded output Channel, spawns one background fiber that loops the input applying the operation, and returns a new Stream wrapping the output, so stages compose left to right as the calls read. Backpressure is free: a full bounded output Channel parks the stage's producer and that park propagates all the way upstream, so a slow `consume` throttles the raw producer instead of buffering unbounded memory. A stream ends when its source Channel shuts down: each stage's fiber sees the shutdown as `undef` from `get`, flushes any partial batch, shuts its own output down, and the chain unwinds fiber-by-fiber back to the source, so no stage parks on a dead source and no orphan fibers leak. `batch_time` groups by an absolute deadline re-armed via get-with-deadline, so a batch fires even when no further items arrive and is emitted as a partial final batch on shutdown, like `batch`; `throttle` paces to at most `$per_s` items a second by sleeping only the remainder to the next slot and never trying to catch up after backpressure. `consume` is the terminal stage - batches are spread into the callback's `@items`, anything else passes whole - and returns a fiber handle you can `await`. `shutdown()` releases a parked consumer end-to-end; `chain()` and `cap()` introspect the pipeline. Tested by t/057: map/filter/batch in order, direct backpressure (a slow consume parks the upstream producer), batch on count and on deadline, throttle capping the rate, and teardown with zero leaked fibers.
- Transparent unblocking: `Acme::Parataxis::Compat` installs `CORE::GLOBAL` overrides for `sleep`, `read`, and `sysread` so legacy synchronous code becomes cooperative without rewrites, gevent-style. It is opt-in dark magic - `Acme::Parataxis->enable_transparent_unblocking()` installs, and only code *compiled after* the call is affected, because every override delegates to the raw `CORE::` builtin outside the scheduler (top level, worker threads), so nothing changes unless you ask it to. `sleep` maps to `await_sleep` at millisecond precision - fractional seconds are honored and the return value is the requested duration - and yields the fiber instead of parking an OS thread. `read`/`sysread` park on `await_read` until the handle is readable and then perform one real read; the buffer is written back through the caller's aliased argument (the compiler passes the second argument by value to a prototyped `CORE::GLOBAL` override, so the overrides are deliberately unprototyped), and a handle the readiness probe cannot watch - a regular file or a pipe - falls back to the raw builtin, which regular files answer instantly. `disable_transparent_unblocking` restores the saved globs and `transparent_unblocking()` reports the state. The article's own framing applies: `select`, `alarm`, `time`, and C-level calls like `DBI` are not covered - use `await_read`/`await_write` or a worker thread explicitly. t/058 covers opt-in and idempotence, raw `CORE::` semantics outside the scheduler, cooperative `sleep` (including the implicit `$_`), framed reads over a loopback pair, top-level buffer filling, the regular-file raw fallback, and disable/restore.
- Full park-site backtraces: every park now hangs a bounded, user-side callchain off its `wait_reason` record, so the record read via `$fiber->wait_reason` (and on the interruption errors) is `[ $reason, $file, $line, $backtrace ]` where `$backtrace` is an arrayref of `[ pkg, file, line, sub ]` frames running from just below the wait back to the fiber body, with library frames filtered out. `dump_fibers()` exposes the chain in its records and prints it as indented `at` lines in the human report, and the scheduler's `FATAL: deadlock detected` message lists each parked fiber's chain back to user code - the perl-level trace #7's deadlock tracing asked for. The capture runs at every park (a short `caller()` walk), so it is configurable and bounded: `backtrace_depth( $n )` (class method, also exported) sets the cap, defaults to 6, and `backtrace_depth(0)` disables the capture entirely for a zero-cost diagnostics path; measured against the spawn/await micro-benchmarks the default capture is within noise. t/059 covers the chain shape and ordering, empty chains for waits reached straight from a fiber body, the depth cap, the kill switch, the human report, and the deadlock report.
- Future combinators: `wait_all( @futures )` and `wait_any( @futures )` aggregate any number of `Acme::Parataxis::Future` objects into a single future without awaiting on your behalf (and work outside the scheduler too). `wait_all` resolves once every input has settled: with no failures its value is one `[ ... ]` arrayref of every input's result in input order, and when any input fails it settles with a wholesale copy of the first failure (reject-fast, `Promise.all` style) without cancelling the others - so `await( wait_all( @f ) )` croaks with the first input's error while the losers keep running and their later results are dropped. `wait_any` (Promise.race) resolves the moment the first input settles - success or failure, copied wholesale - so `->error` on the aggregate distinguishes a winning result from a winning failure. Both accept an empty argument list (all resolves immediately with `[]`) or reject a non-future input, and both are callable as exported functions or as `Acme::Parataxis->wait_all( ... )` / `Acme::Parataxis->wait_any( ... )` class calls that are exempt from the one-arg ambiguity. `Acme::Parataxis::Future` gained an `error()` accessor (raw stored error, `undef` until the future fails) to tell success from failure without croaking, and the general `await( $target )` / `Future->await` delegation the combinators' aggregate futures ride on. t/060 covers zero-input all, ready-input inline resolution, input-order results, reject-fast with losers un-cancelled, mixed ready/pending, wholesale race copies, class-callable forms, non-future input croaks, and the `error()` accessor.
- `pmap( { concurrency => $n, }, sub ( $item ) { ... }, @items )`: a parallel `map` over a bounded fiber pool. `@items` are handed to at most `$n` concurrent worker fibers at a time (any positive integer; default one worker per item, capped at the item count) and the results come back in input order even when items finish out of order, returned as a list or arrayref per `wantarray`; an empty list returns immediately. Mappers may `await`, park, or use any primitive - each runs in its own worker fiber. When an item's block dies, that first error is recorded and the pool is cancelled: siblings stop at their next item boundary, cancelled worker errors are suppressed, and `pmap( )` rethrows the recorded error once every worker has drained, so no fiber outlives the call. Like `nursery`, `pmap( )` must be called from inside a scheduled fiber, junk in the option hash above `concurrency` is ignored, and an enclosing `with_timeout`/`nursery` interrupt cancels and drains the pool before the caller's own error is rethrown. t/061 covers ordered results, the concurrency cap and defaults, empty input, mapping errors cancelling the pool, cancellation of severally mapped items, and a subclass-callable form.
- `with_cancel( $code )`: cancellation *scopes*. The block runs on the calling fiber (no child is spawned) and every blocking wait it enters is automatically interruptible by one token - the scope token `with_cancel` returns - so callers stop threading a token into each primitive. Cancelling that token interrupts a wait parked right now and stamps the fiber so the next wait entered inside the scope fails fast; scopes nest LIFO, share the park with a `with_timeout` deadline or a `nursery` token, and unregister their waits on every exit. The return convention is context aware (token alone in scalar/void, token prepended to the block's value(s) in list context); a block's own error propagates unchanged, and a cancel that arrives while the block still completes is rethrown at the scope boundary as `Error::Cancelled` (or `Error::Timeout`) rather than swallowed. t/062 covers interior interruption, already-finished waits staying done, post-exit no-op cancels, LIFO nesting, composition with `with_timeout`, no leaked registrations, and argument validation.
- `Acme::Parataxis::Monitor`: observe another fiber's death without owning it, like an Erlang monitor. `Monitor->new($fiber)` (or `fid => $id`) returns a `Future`-like handle that resolves exactly once when the target exits - `undef` for a clean end, the death error for a crash - by riding the target's existing `on_ready`/`on_death` slot, so it needs no scheduler change and never delays the target's reaping. Watching an already-dead target fires immediately; the completion callback captures the monitor weakly, so dropping a monitor lets it dissolve instead of lingering in the target's callback list. It watches fibers, futures, and actors alike. t/064 covers clean and crashed targets, already-dead targets, single resolution, id-based watching, nursery children, actors (graceful stop vs supervised crash), the run root, and unwatchable targets.
- Actor hot code swap and a named registry: `Actor->spawn( ..., name => $name )` registers the actor process-wide in the style of Erlang's `register` table, and `Acme::Parataxis->actor($name)` / `->whereis($name)` (or a plain `Acme::Parataxis::actor($name)`) returns the handle - or `undef` for a name nobody holds. A second live registration under the same name croaks like `register` (the name is reusable once its holder is gone), and the name is released when the actor stops, crashes, or is destroyed, so a dead actor never answers a lookup. The registration is a strong reference, so a named actor outlives every caller that drops its handle until it is stopped - the name is the handle - and `respawn()` inherits the name, so a supervised actor keeps answering its registry key across restarts. `$actor->swap($code)` hot-swaps the handler atomically at the next message boundary: a message already in flight finishes with the old code, every message dispatched after `swap` runs the new code, and the whole swap is a plain field read per dispatch - no drain, stop, or rebuild. t/065 covers lookup and the `whereis` alias, name release on stop and on a supervised crash, spawn collision and reuse, bad-name validation, in-flight-old/post-swap-new dispatch, double swap, swap argument and dead-actor croaks, respawn keeping the key, and the registry as a strong handle with a clean teardown.
- `Acme::Parataxis::Channel` accepted a per-channel default wait bound: `Channel->new( ..., timeout => $ms )` gives every `get` and `put` a deadline without threading one in by hand. A `get` or `put` that would park is bounded by the bound and dies with `Acme::Parataxis::Error::Timeout` (the waiter unregistered from the internal semaphore) when it expires, using the same shared-deadline-token machinery as `select` - the token is registered once, reused across the semaphore's re-parks, and the teardown recalls the armed timer job on every exit so a wait that ends early never leaves a worker sleeping out the bound. `timeout => 0` (the default) and `timeout => undef` disable the bound, and it is read back via `$ch->timeout`. `select` composes: an explicit `timeout` option still wins, but without one each case's channel default applies and select parks until the earliest fires. `try_get`/`try_put` stay non-blocking and ignore the bound. t/018 covers get/put timing out at the bound, an unexpired wait still interruptible by `with_timeout`/cancellation, a producer beating the bound, `timeout => 0` disabling the bound, `try_*` unaffected, and no stray sleep job or waiter after a wait ends; t/041 covers select honoring a channel default, the option winning over the defaults, and the earliest default winning when cases disagree.
- Trace propagation: `Acme::Parataxis::Local->new( ..., inherit => 1 )` opts a slot into upward seeding. The value it holds is copied from the spawning fiber into each child the moment the child is born - via `fiber`/`spawn`, a `nursery` child, or an actor's mailbox fiber - as a shallow copy the child then owns exclusively, so later `set`s never cross either direction (exactly per-fiber isolation, only seeded). The seed is captured at the spawn call, before `spawn`'s eager body run, and applied by a wrapper running in the child, so the child's first read already sees it; a plain `Local` keeps strict isolation, and when no inherit slots (or no set values) are in play no wrapper is built and the common spawn path is untouched. t/068 covers first-read presence, child writes invisible to the parent, plain isolation, the pre-spawn seed (post-spawn writes do not propagate), nested inheritance, nursery children, actor birth, an unset slot falling back to its default, and spawn-level croaks/results staying intact.
- Deterministic mock time: `run( virtual => 1, code => sub { ... } )` switches every timer-based wait in the run onto a virtual clock the test drives, so a 1-hour timeout is exercised in microseconds. While the mode is on, `await_sleep`, `with_timeout` deadlines, `select` timeouts, `Channel` wait bounds, `Ticker`, `RateLimiter`, and `Stream` timeout reads all consult `Acme::Parataxis->mock_time()` / `->virtual_now()` and arm virtual timers instead of kernel sleeps; the scheduler fast-forwards the clock to the earliest pending deadline only when nothing is runnable and no jobs are outstanding, so real work and real I/O always run first. The test nudges time with `Acme::Parataxis->advance( $ms )` (fires every deadline up to and including the new time; woken fibers resume on the next scheduler pass), and virtual state is scoped to the outermost virtual run - nested runs ignore the flag, the clock starts at zero each run, is torn down at the end, and ordinary `run()`s are untouched; `advance()` croaks outside a virtual run. t/066 covers the 1h `await_sleep` in under a second, a 1h `with_timeout` firing under advance, `Ticker` landing on exact virtual boundaries, `RateLimiter` refilling on a one-millisecond advance, `select` and `Channel` bounds firing on advance, earliest-deadline-wins ordering, a busy fiber outrunning the clock, and no virtual state leaking between runs.
- Graceful shutdown: `run( on_shutdown => $opt )` makes the outermost run install `SIGINT`/`SIGTERM` handlers for the run's lifetime (restoring the previous handlers afterwards). The first signal fires the run's shutdown `CancellationToken` and interrupts every fiber the run created - the root fiber included - so they throw `Error::Cancelled`, unwind, and run their own cleanup (defers, `DESTROY` blocks); once everything drains, `run()` returns the conventional interrupted status (130 for SIGINT, 143 for SIGTERM) instead of rethrowing the cancellations, and a second signal restores the previous handlers and re-raises the signal so the default disposition kills the process - the handler never blocks a second Ctrl+C. The option accepts a plain true value, a code ref (called on shutdown with the already-fired token, for flushing logs or stopping servers), or a pre-made `CancellationToken`, whose `cancel()` from anywhere begins the same drain in-process - no OS signal required. `run()` without the option leaves `%SIG` untouched, nested runs ignore it, the named-argument parse now accepts `code`/`virtual`/`on_shutdown` in any order, and the scheduler stays reusable after a shutdown. t/069 covers the option plumbing (`%SIG` left untouched without the option and restored after it, the callback not firing on a normal completion, unknown options and bad `on_shutdown` types croaking, nested runs ignoring it), the full token-driven interrupt/drain/status path on every platform, and - where real signals are deliverable (not MSWin32, same skip as t/003) - a subprocess harness asserting SIGINT returns 130 with a drained `READY/DEFER_RAN/DESTROY_RAN/DRAINED:130` log, SIGTERM returns 143, and a second SIGINT hard-kills the process mid-cleanup.
- Fiber cleanup via perl's native `defer` (experimental, v5.36+): a `defer` written lexically inside a fiber body fires exactly when the fiber's scope exits - on a normal return, on a `die`, and on cancellation (a token interrupt or `with_timeout` deadline unwinds the parked fiber's scope, so the `defer` runs on the way out) - before the coroutine is reaped, so a fiber that acquires a lock, opens a handle, or registers on a token gets its release on every exit path with no library API and no scheduler change. Blocks run LIFO, each exactly once, for run-level children, nursery children, and actors alike; a `defer` that itself dies becomes the fiber's throw to its `await`-er (or chains after the body's own error). Two footguns documented in the pod: perl's `defer` is *block-scoped* (a `defer` in a nested block or helper sub fires at that scope's exit, not the fiber's), and it is an experimental feature needing `use experimental 'defer'`. t/063 covers LIFO, return/die/cancel (token and deadline) paths, a dying defer folding into the awaiter error, doubled registrations, nursery children, and the fiber slot being released.
- Waiter introspection and removal (the foundation for cancellation): blocking waits now park through a single `_park`/`_resume_hooks` path that records a `wait_reason` (a label plus the calling file/line, readable via `$fiber->wait_reason`) and fires `on_wake` hooks exactly once when a parked fiber is resumed. `Semaphore`, `Signal`, `Future`, and `Channel` each gained `remove_waiter` to un-register a parked waiter.

### Fixed

- A fiber that completed after one or more yields could longjmp into freed stack memory (0xC0000005) while dispatching its completion callbacks: the jump environment pushed around the body was popped before the callbacks ran, so a callback that died made perl longjmp to the caller's `PL_top_env` on a different stack. The fiber-entry jump environment is now held for the fiber's whole lifetime and each fiber's `top_env` is saved/restored across context switches, so a die during completion stays on the fiber's own stack.
- A `run` that dies with `FATAL: deadlock detected` now leaves the scheduler reusable: `$IS_RUNNING` is cleared and the run queues emptied before the message is thrown, instead of poisoning every subsequent `run`/`async`. The deadlock detector also snapshots the fibers alive before the run starts, so fibers leaked by an earlier deadlocked run can no longer make a healthy later run look deadlocked.
- A scheduled fiber that dies while another fiber is awaiting it (or has an `on_ready` callback) no longer takes down the whole run loop: the error is delivered to the awaiting fiber's `await` instead, matching Coro-style rethrows.
- `await_sleep` now sleeps the full requested duration instead of inflating it: the worker's `TASK_SLEEP` branch waits on the queue condition variable with a timed wait (`SleepConditionVariableCS` on Windows, `pthread_cond_timedwait` on POSIX) rather than polling in 4ms quanta, so `await_sleep(1000)` returns in ~1s (Windows previously ~4s, because each `Sleep(4)` rounded up to the ~15.6ms timer tick) and 20ms deadline timers fire near their bound. `recall_sleep_jobs_for_fiber` now broadcasts the queue condvar, so an interrupted sleep aborts in sub-millisecond time instead of within one quantum.
- Fixed the crash when destroying a parked fiber: destroying a fiber while it was still parked freed its live activation slots in the shared PadLists and touched the global `CvDEPTH` counters of the subroutines it was inside (`yield`, the wait helpers, ...), corrupting the *next* fiber that activated one of those subs and crashing the interpreter with a 0xC0000005 in `Perl_clear_defarray` - usually one id-reuse round later. `destroy_coro` now only unwinds pads when the fiber's context stack has been unwound to exhaustion (`si_cxix < 0`, i.e. reaped after finishing); a parked fiber's shared slots are left for normal later reuse and its closures release their pads with the body CV, so destroying a parked fiber is safe. Regression-tested in t/046. The `with_timeout` re-park branch that used to guard against this crash is retained so an abandoned child dies through its own cancellation path rather than being yanked.
- Restored Perl's canonical REIFY-only state for `@_` landing pads during fiber context switches: `_activate_current_depths` Pass 2 now uses `AvREIFY_only` instead of the bare `AvREAL_off` it had flipped since v0.0.9. Flipping only `AvREAL_off` left a pad's slot 0 in Perl's invalid neither-REAL-nor-REIFY state, which a later `Perl_av_store` could re-turn REAL and make a `DEBUGGING` build abort in `Perl_pp_entersub` (`assert(!AvREAL(av))`, pp_hot.c line 6447) - the intermittent `t/040_nursery.t` Stress failure seen on every recent push. `AvREIFY_only` restores the exact state `pad_push`/`clear_defarray` guarantee, so the invariant survives re-entry.
- A worker pool can no longer starve on an idle queue: `submit_c_job` now broadcasts (not just signals) the job-queue condition variable, so a worker parked inside its timed sleep wait (re-checking only its absolute deadline) wakes immediately to claim a freshly submitted `JOB_NEW` instead of sleeping out the rest of its bound - previously a single signal could be swallowed by a worker that went straight back into its timed wait, leaving the new job unclaimed (and the fiber awaiting it parked) until some unrelated long sleep finally woke the pool.
- Fiber-parking subs (`yield`, the `await_*` family, `await_sleep`, `with_timeout`, `spawn`, `nursery`) no longer leave a reified `@_` behind when they park: each resolves its first argument's offset through `_arg_offset` (which reads the slot without reifying the caller's pad), empties `@_` before parking, and only pulls the sub itself out of the array when it was actually invoked with one. A reified `@_` left sitting in a parked frame would later trip `Perl_pp_entersub`'s invariants (`assert(!AvREAL(av))` / `assert(AvFILLp(av) == -1)`) when a *different* fiber activated the same sub at the same depth - the companion to the REIFY-only landing-pad restore above, making the pad invariant survive even when the parked sub's own args were visible.
- `exit()` from a fiber that had already yielded (e.g. after `await_sleep`) no longer segfaults in `__longjmp` with an unreadable jump target: the fiber's saved `top_env` points at the previous resume's already-popped `coro_call` guard, so the raw longjmp jumped to freed stack memory (`POSIX::_exit` was unaffected because it never longjmps). The fiber-aware `exit()` interception - opcode hook, fiber-stack catch in `para_entry_point`, re-raise on the caller stack in `coro_call` - that previously existed only on Windows now applies on every platform. Regression-tested in t/021.
- The thread pool no longer stalls a freshly submitted job behind unrelated long sleeps. `submit_c_job` grew the pool only after counting jobs that were *already* pending, and before inserting the job it was submitting, so a lone submission against a pool whose every worker sat in a long `TASK_SLEEP` saw `pending == 0`, spawned nothing, and queued until one of those sleeps ended: a 10ms `await_sleep` submitted while a 400ms `with_timeout` timer and a 600ms sleeper held both seeded workers woke at 400ms instead of 10ms, which is what made `with_timeout` look broken whenever a third fiber happened to be sleeping. Growth now runs after the insertion and spawns exactly the deficit (`pending - idle`, with a worker counted busy from the moment it claims a job until it marks that job done), bounded by the configured pool size. The default pool size also gained a floor of 8, so a machine reporting 1-2 cores can no longer pin it at the 2-worker seed and reproduce the stall by construction. Regression-tested in t/052.
- A shared subroutine no longer loses its lexicals when one fiber parks inside it while another parks deeper. `CvDEPTH` is a single shared counter per CV: when shallower frames left, it dipped below the depth of a frame some other fiber had parked there, and the next entry landed on that parked frame's pad and wiped `$self`, `@_`, and the `my` lexicals in place (instance-backed fields survived, so the victim typically died with an undefined receiver a few calls later, long after the actual park). This is what the supervision trees' extra nesting depth flushed out, and it is a genuine scheduler bug rather than a supervisor bug: `_activate_current_depths` now keeps a per-CV registry of parked depths, sets `CvDEPTH` to the deepest parked frame (plus the core's own `olddepth + 1` convention for frames still on the resuming stack, which `cx_popsub_args`' DEBUGGING assert requires), and only cleans a landing pad that no parked frame owns, so a resume can never step on a pad another fiber is parked in. A fiber's registrations are purged when it is destroyed. Regression-tested in t/055 with the exact four-fiber choreography (park, dip, re-enter, park again) that used to wipe the victim.

### Changed

- The default fiber limit is now 65536 rather than 1024, so a program that assumed spawning past 1024 would croak keeps going until it hits the new limit. The old behaviour is still available by pinning `set_max_fibers(1024)`.

## [v0.1.0] - 2026-09-21

This started as a silly little diversion in February but I'm using this in actual projects now. I've even used it to shake out bugs in Affix.

I might move it out of the Acme namespace...

Anyway, the major win is that fiber hot path has been moved from Perl into C and roughly tripled context swapping throughput with no change to the public API.

### Added

- `Acme::Parataxis::Channel`: a buffered FIFO message queue for producer/consumer patterns between fibers. Writers block when full, readers when empty; a capacity of `1` makes it a rendezvous point. Built on two semaphores.
- `Acme::Parataxis::Future`: a one-shot placeholder for an eventual computation result. A producer fires `set_result`/`set_error` exactly once; consumers pick it up with `await`/`result` or register an `on_ready` callback.
- `Acme::Parataxis::Semaphore`: a counting semaphore with no ownership: blocked fibers are parked (no busy-wait) and resumed FIFO as permits become available.
- `Acme::Parataxis::Signal`: a two-state flag with a FIFO queue of waiters. `send` latches the signal so a later `wait` consumes it immediately, while `broadcast` wakes every queued waiter at once (and drops if nobody is waiting).

### Fixed

- Fixed crash (double-free / use-after-free) when fibers call Affix'd functions on non-threaded Perl. The bug was in Affix's `SAVEVPTR`/`SAVEDESTRUCTOR_X` arena pattern, which was not fiber-safe; now fixed upstream in Affix v1.2.5+.
- Fixed SIGSEGV on macOS and FreeBSD caused by fiber stacks being only 512KB (via `posix_memalign`). All POSIX platforms now use a 64MB `mmap`-backed stack with a PROT_NONE guard page, matching the Linux path. The SIGSEGV guard handler is also available on macOS/FreeBSD now.
- Fixed FreeBSD compilation: added `MAP_ANONYMOUS` w/ `MAP_ANON` fallback.
- Fixed macOS SIGBUS: the guard region size is now derived from `sysconf(_SC_PAGESIZE)` at runtime so it always covers at least one full page (16 KiB on Apple Silicon). Also fixed `cleanup()` to use `munmap()` instead of `free()` on non-Linux POSIX platforms.
- `is_finished()` now rejects fiber ids of `MAX_FIBERS` or greater instead of reading out of bounds of the fiber table.
- Closed a busy-spin footgun: `wait`, fiber `await`, `Semaphore` waits, and `Signal->wait` now croak instead of burning 100% CPU when called from outside the scheduler, and `->new` croaks when the 1024-slot fiber table is exhausted rather than creating a fiber that can never run.
- A fiber that yields during its initial run is now re-enqueued by the scheduler instead of being dropped, which previously could hang a regex-heavy workload.
- The scheduler no longer hangs when a fiber object is created but never spawned (`->new` without `spawn`): live-fiber tracking only counts fibers that have actually started, matching Coro's ready-queue semantics.
- `async`/`run` is now re-entrant: a nested `async` inside another `async` or inside a fiber shares the one run loop (like Coro's single global scheduler) and returns the block's value, instead of clobbering the outer scheduler and deadlocking.
- A destroyed fiber's id is kept out of the free list until every job it submitted has been reclaimed, so a stale completion can never be misdelivered to a (or corrupt) fiber that later reuses the id.
- Pending-job tracking now reads the C-side outstanding job count instead of a run-local counter, so jobs left over from a `stop`ped run are drained and handled by the next run instead of tripping `FATAL: deadlock detected` or sitting in the done-queue forever.
- `Semaphore` `up`/`adjust` skip stale (already destroyed) waiters instead of consuming a wake that should go to a live fiber.
- Channel constructors now reject a capacity below 1 instead of deadlocking on it at load time.
- The 1024-slot job queue is no longer fatal on the first try: `_submit_job` yields once and retries before croaking.
- `Future::set_result`/`set_error` wake awaiters exactly once instead of appending a duplicate `_wake_waiters` callback on every `await`.

### Changed

- Spawned fibers run inline at spawn time.
- The fiber registry is replaced by strong references to each fiber object in C.
- Fiber completion moved from a Perl method into C: the entry point writes state directly into the object's slots with `av_store`, and only dispatches callbacks when callbacks were actually registered.
- To save time on FFI boundary crossings, `spawn` now performs the whole create run sequence in a single call and builds the fiber object in C.
- Fiber objects are incrementally-filled AV*s instead of HV*s.
- On x86_64 ELF, context switching uses a hand written trampoline that only saves the callee-saved registers and stack pointer, avoiding `swapcontext`'s signal-mask syscall.
- `spawn` and `await` hot paths flattened by inlining helpers.
- Worker threads block on `select()` for the full `await_read`/`await_write` timeout instead of polling every 10ms, cutting idle syscalls by ~50x. On POSIX a shutdown pipe wakes any worker blocked in `select()` during `cleanup()`.
