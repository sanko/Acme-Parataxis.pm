  - `Generator.pm`'s fiber-local `eval` is load-bearing: it catches a `die` raised on a *resumed* trip, which the scheduler's own `G_EVAL` can miss. Verified empirically that `try`/`catch` behaves identically across a fiber suspend/resume before converting it.
  - Three traps found the hard way, do not undo them:
    1. `catch (VAR)` does **not** assign to a pre-declared outer lexical -- the value is only visible *inside* the catch block. Write `catch ($caught) { $err = $caught }`, never `catch ($err) { $ok = 0 }`, or `$err` silently stays `undef`. This bit `TVar.pm` and `Nursery.pm` in the first pass, and `Actor.pm` again later. `perl -c` is happy either way and the suite does *not* catch it, so audit new `catch` sites by hand.
    2. `try`/`catch` are stable, but `finally` is **experimental** and warns at compile time. The three files that use it are covered: `TVar.pm` and `Channel.pm` got `experimental::try` added to their `no warnings` line, and `Acme/Parataxis.pm` already had `use experimental qw[class try]`.
    3. `catch` must come *before* `finally`, and a `catch` that drains children must not reuse the parent's error variable or the rethrow is corrupted (`Nursery.pm` and `pmap`).
  - Converting `Channel.pm` fixed a real bug rather than just restyling: `_with_deadline` had `$ok = eval { $rv[0] = $op->() }` followed by `die $err if !$ok`, so it read the *get's return value* as its own success flag and a channel holding `0` or `''` came back as a bare `Died`. Regression test added to `t/106_coro_channel.t` plus a `Changes.md` entry. Same bug class as the old `run()` entry, so the rule is: never let an `eval`'s return value be the success flag.

  - **What `Test2::Tools::Exception` actually provides**, verified by probing the installed 5.44.0 copy rather than trusting the docs:
    - `dies`/`lives` take **one argument only** and emit **no assertion of their own**. `dies { ... }, 'desc'` silently discards `'desc'`, and the assertion always comes from the surrounding `ok`/`like`/`is`. Only the third primitive, `try_ok`, calls `$ctx->ok` itself.
    - `dies` returns the exception **with its class intact** (a blessed `Error::Cancelled` stays blessed, so `ref($e)->isa(...)` survives) and `local`s `$@`. So the reason must be taken from its **return value, never from `$@`** -- `ok( dies { X }, 'd' ); like "$@", qr/.../` silently reads the *pre-call* value. This cost 4 failures once, and it is why every `ok !eval {...}` + `like "$@"` pair had to convert **together** rather than one site at a time.
    - `lives` returns **1 or 0, never the block's value**, and it does not clamp (`lives { 0 }` is `1`).
    - Both have prototype `(&)` but it is **not** honoured for imported subs, so `dies { ... };` as the first token of a statement is a **syntax error**. They only parse in list-operator position (`like dies {...}, ...`, `my $x = lives {...}`) or with explicit parens.
  - `lives` was verified to be a faithful 1:1 for `eval { ...; 1 } or $err = $@;` -- it returns 0 and sets `$@` on failure, returns 1 and leaves `$@` untouched on success (`/tmp/opencode/probe_lives.pl`). That is what `t/355_shared_pads.t`'s two `or $err = $@` sites use. A `dies` rewrite there would have been **wrong**, not just clumsy: `dies` returns the error unconditionally and would clobber an already-recorded one.
  - **The `my $x = eval { B; 1 }` flag is context-dependent and was deliberately not scripted.** `dies` returns the *error* (truthy when it DIED), `lives` returns 1 (truthy when it LIVED) -- opposite senses. So `ok !$x` becomes `ok $x` under `dies` but `ok $x` stays as-is under `lives`, and `t/302_mock_time.t` and `t/503_shutdown.t` needed a variable renamed (`$adv_msg` and `$out` held a *flag*, not a message). All 13 were read by hand. Same rule that caught the `Channel::get` bug: never let an `eval`'s return value be the success flag.
